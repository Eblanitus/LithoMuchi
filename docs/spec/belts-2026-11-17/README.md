# Биомы против температурных поясов (2026-11-17, `main` 4a12a8c, `v1-dev`)

Вопрос автора: «"жарко" внутри пояса не бывает выше пояса. Пояс и есть температура. Если
где-то реально жарко, это уже следующий, тёплый пояс». Соответствуют ли этому наши биомы?

Код не менялся. Замер — `beltprobe.rs` (отдельный крейт рядом с `litho-core`, путь к
ядру в `Cargo.toml` поправить под себя): сетка 240×240 точек на квадрате ±64 L (одна
клетка полюсов, все широты), сиды 42 и 7, оба режима, быстрый путь `Generator::sample`.
Суша 18,6–26,3 тыс. точек на прогон. Сырые выводы — `out-*.txt`.

## Вывод: частично, скорее нет

Есть два разных «пояса», и в этом главная путаница.

1. **Пояс в коде (П0–П6)** считается по биотемпературе *после* всех поправок:
   континентальность, высота К5, шум. Поэтому «где реально жарко — следующий пояс»
   код выполняет буквально, но пояс перестаёт быть широтной полосой: 36–40 % суши стоит
   в другом поясе, чем говорит широта (видимо по ванильной строке T — 3–13 %).
2. **Внутри своего же пояса** код ставит биом из другой строки на **5–19 % суши**:
   правило суровой зимы ❄ и замёрзшие реки кладут снежные/ледяные биомы в бореальный и
   умеренный пояса. Это прямое нарушение определения.

Относительно чисто широтного пояса (широта + постоянный вычет суши 3,5 °C, морской
климат, без высоты и шума) итоговый биом не из своей строки на **3,3–8,9 % суши**.

**Двойной учёт континентальности.** Биотемпература считает только месяцы выше 0 °C
(`climate.rs:347–355`), поэтому в глубине материка жаркое лето поднимает пояс
(П1 → П2/П3). Одновременно морозная зима (`T_min`) через ❄ опускает биом на строку
холоднее. Где пояс поднялся на другую ванильную строку (13 % суши сид 42, 3,4 % сид 7),
в 92 % случаев зима вернула биом на строку широты. Пример: сид 42, X 2867 Z 2333,
φ 59,7° (по широте полярный/тундра) → пояс П2 бореальный по лету → `snowy_taiga` по
зиме −28 °C. Карта выглядит разумно, но «пояс» и «биом» говорят разное.

Про «в 30 раз сильнее земного»: это если блок = метр. В нашем мире горы в 4–8 км
модели стоят на 100–250 блоках; в научном режиме 24 блока на км (`e_gain_blocks_per_km`),
то есть 0,2 °C на блок ≈ 4,8 °C на км модели — даже слабее земных 6,5. Беда не в
наклоне, а в том, что вычет вообще меняет пояс на холмах y 140–170 и что он сдвигает
пояс, а не только ставит шапку.

## Рекомендация

1. **Один пояс — одна температура.** Пояс = широта + постоянный вычет суши (+ при
   желании сдвиг среднего от континентальности). Убрать из пояса «летнюю»
   биотемпературу (обрезку месяцев ниже 0) и вместе с ней правило зимы ❄: они гасят
   друг друга в 92 % случаев, карта почти не изменится, зато пропадёт двойной учёт.
   Пороги поясов переподобрать замером, чтобы доли 10.1 не уехали.
2. **Строка T биома — только из пояса.** Влажность выбирает столбец внутри строки.
   Накладки воды строку не меняют: `frozen_river` только в строке t0
   (`hydrology.rs:250`), болото и галерейный лес меняют только h.
3. **Высота — только шапка.** Вместо −0,2 °C/блок от y 120: порог «гора» (по замеру —
   от y ~170, ниже вычет меняет строку редко), выше — снежная шапка, пояс вокруг не
   трогать. В ванили снег по высоте уже есть у тайги (с y ~160) и `windswept_hills`
   (с ~120): это готовая шапка по настоящей высоте.
4. **Кайма пустыни** — песок и саванна только с П4, в П3 сухо = равнины (мелочь,
   0,2–0,3 %).
5. **Ванильные снежные склоны на холмах y 115–140** — проверить в игре на А2. Если
   подтвердятся, давать E0–E1 с высоким |W| только там, где наша высота реально горная.

Пункты 1–2 убирают около 95 % нарушений против пояса кода (строки 1, 2, 6, 8 таблицы).
