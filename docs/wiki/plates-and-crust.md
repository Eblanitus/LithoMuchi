# 2. Плиты и кора

Статус: числа сверены с `docs/PARAMS-V1-DEV.md` (генерируется из `params.rs`) на
2026-11-14. Формулы — [спецификация v1.0, разделы 7.3–7.4](../spec/PLAN-v1.0-2026-11-06.md#73-литосферные-плиты);
ниже только то, что изменилось после неё, и текущие числа.

## Плиты (spec 7.3)

Как в спецификации: семена в ячейках `G = 16 L`, Вороной после искажения домена,
поиск в окне 5×5 ячеек, тип границы из относительной скорости (`γ_conv`, `γ_div`,
`γ_tr`), тройные сочленения с весами `exp(−d/0,4)`.

Текущие числа (одинаковы в обоих режимах, в блоках `G` = 16 000 научный / 4000 геймплейный):

| Параметр | Спецификация | Сейчас | Решение |
|---|---|---|---|
| амплитуда искажения границ `warp_amplitude_l` | 1,6 L | 4 L | Д-011 |
| пустая ячейка `empty_probability` (только чётные индексы) | 0,35 | 0,22 | Д-021 |
| два семени `double_probability` | 0,25 | 0,35 | Д-021 |
| материк на плите `continent_probability` | 0,5 | 0,45 | Д-012, Д-021 |
| радиус материка | 4–9 L | 2,5–17,5 L, степенной разброс `continent_radius_skew` 2,2 | Д-012, Д-021 |

Известная особенность: плиты получаются почти одного размера. Медиана поперечника
15,6 L, самая маленькая 7,9–10,5 L (замер `metrics124-plates-1`, Д-078), разброс узкий,
потому что семена стоят по сетке с дрожанием. Это следствие схемы spec 7.3.1, не ошибка
кода. У Земли распределение плит степенное. Менять — отдельное решение.

## Материки (spec 7.4.1 изменена)

- Поле материка `κ` больше не берётся от ближайшей плиты со смешиванием через границу
  (`κ_mix`). Оно равно максимуму вкладов всех центров материков в окне ячеек
  (`kappa_global`, окно `continent_query_radius_cells` = 4, то есть 9×9). Материк может
  лежать на нескольких плитах (Д-012, Д-021).
- Береговая рябь: шум `κ` амплитудой 3 L, `λ0` = 6 L (Д-021).
- Тип границы (веса k1…k7) считается по той же доле материка `χ` из `kappa_global` для
  обеих сторон стыка (`boundary_weights_from_chi`, Д-022). Раньше тип брался от эллипса
  своей плиты, из-за чего по стыкам внутри материков шли жёлоба. В коде исправлено;
  в игре отдельно не проверялось.
- Горячие точки по-прежнему берут тип коры от эллипса своей плиты (`crust.rs`,
  `hotspot_height`). Мелкое расхождение с остальным слоем.
- Следствие: береговая линия статистически не связана со стыками плит, у материков нет
  правила «активная окраина = горы у берега». Это слабость схемы, а не ошибка кода.

## Высота коры и профили границ (spec 7.4.2–7.4.6)

Базовая высота по `κ`, профили U1–U7, детализация, `M`, `Pl`, `ι` — как в спецификации.
Отличия по числам:

| Параметр | Спецификация | Сейчас | Решение |
|---|---|---|---|
| горячие точки: ячейка / вероятность / звеньев цепочки | 24 L / 0,3 / 6 | 20 L / 0,45 / 4 | Д-021 |
| высота горячей точки `h_hotspot_km` | 4,8 км | 4,6 км | — |

Горный пояс узкий: `W_col = 0,6 L` (150 блоков в геймплейном режиме). Доля гор на суше
4,4 % при ориентире 5–20 % (ориентир 12.4, см. [metrics-and-acceptance.md](metrics-and-acceptance.md)).
