# Интеграция 0.2.0: два встроенных режима, кэш, диагностика и лава

Дата: 2026-11-08. Продолжение [первого игрового теста](PLAYTEST-2026-11-07.md).
Это реализация и автоматические проверки, не отчёт о новом запуске на Windows.

## Что меняется для игрока

Установить только `litospherity.hnmod`. Создать **новый** мир, тип Normal,
открыть Data Packs. В доступных наборах автоматически появятся:

- **Litospherity - Игровой мир** — горная иконка, меньший масштаб;
- **Litospherity - Научный мир** — иконка планеты, крупный масштаб.

Перенести **один** набор в выбранные, оставить vanilla. Оба набора изначально
выключены. При выборе двух режимов создание мира отклоняется с объяснением.
Smoke не встраивается и не публикуется в обычном артефакте. Разработчик может
получить его через `python tools/package_mod.py --include-smoke`.

Встроенные наборы копируются только в временную папку Create World при открытии
экрана Data Packs; штатный Horizon переносит их в новый мир и сохраняет выбор.
Никаких записей в глобальные ресурсы игры и существующие сохранения. Если набор
с таким именем уже присутствует (например, Re-Create), он не перезаписывается.
Старые миры с прежними ZIP продолжают использовать свои наборы. Для новых
функций тестируйте новый мир: старые наборы намеренно не обновляются автоматически.

## Кэш колонок

Перенесён алгоритм из PR #8 (`75275f1`, автор Claude): 4096 слотов на поток,
ключ `(generator_id, точные биты x, точные биты z)`, все семь значений разом.
Добавлены счётчики запросов/попаданий текущего потока и побитовые тесты.
Кэш около 320 КиБ на рабочий поток, ограничен, без общей блокировки.

```bash
cargo run -p litho-core --release --example bench_columns -- 42 gameplay 2
cargo run -p litho-core --release --example bench_columns -- 42 scientific 2
```

Бенч сравнивает прежние пять полных расчётов с новым путём, проверяя каждое
значение побитово. Два порядка запросов: точка→поля и чанк→поле→точки.
Локальный замер (4 чанка, один поток, сид 42):

| Режим | Пять расчётов | Кэш, точечный порядок | Кэш, полевой порядок |
|---|---:|---:|---:|
| gameplay | 920 мс | 183 мс (~5,02×) | 292 мс (~3,15×) |
| scientific | 906 мс | 181 мс (~5,00×) | 291 мс (~3,11×) |

Это микробенч ядра, **не измерение скорости игры или LOD**. При полевом порядке
попаданий меньше из-за коллизий; результат не меняется благодаря проверке ключа.

## Защита мира от изменения

`golden/v0/world.txt` получен из реализации генератора до колонкового кэша,
из коммита `8beb6ac` (копия исходников компилировалась отдельно). Содержит
3 сида × 2 режима × (32×32 сетка с шагом 3,7 L + 32 псевдослучайные точки):
6336 точек. Сверяются биты C/E/W/T/H, высоты, осадков, биотемпературы,
сдвига спавна, а также класс зоны. Сумма полей не используется как доказательство.
`tools/world_snapshot.rs` — общий код записи, тест `golden_world` сравнивает
строки с зафиксированным файлом. Эталоны не обновляются автоматически в тестах.

Новый аквиферный путь лавы — отдельное намеренное изменение подземной жидкости,
он не включён в обещание неизменности пяти полей/рельефа.

## Диагностика стены и климата

В игре (данные также записываются в latest.log):

```text
/litospherity probe <seed> gameplay -1797 -630
/litospherity probe <seed> gameplay 1287 832
```

В песочнице:

```bash
cargo run -p litho-sandbox --release -- diagnose --seed <seed> --mode gameplay --at -1797,-630
```

Вывод одинаковой функции: параметры, значения и биты пяти полей, температура,
осадки, высота, зона, локальные скачки C/E/W и значения лавового поля.
**Это расчёт для явно введённых seed/mode, не автоматическое чтение активного
мира и не ID реально выбранного игрой биома.** ID биома проверять отдельно.
Без сида и повторного игрового теста стена и соседство мезы/льда остаются
открытыми наблюдениями, а не объявленными исправленными багами.

## Лава: выбран вариант «только аквиферы»

Хук изменяет только `settings_json.aquifers.lava`, только в
`OverworldGenerator::for_world_with_settings`, для `minecraft:overworld`
с ровно одним маркером нашего активного пака. Nether, End, чужие измерения,
миры без наших паков и smoke не меняются. Исходные настройки Mojang не копируются.

- Наша плотность лавы получает блочные координаты через масштабы **64/40/64**.
- На ячейках ниже Y=-40: `lambda * (0.2 + 0.8 * deterministic_cell_random)`.
- Lambda берётся из близости к границам плит, без дорогого расчёта климата.
- На ячейке −1 (она покрывает блоки −40…−1) и выше сохраняется оригинальная функция лавы игры.
- Барьер, уровень жидкости, поверхность и остальные поля аквифера сохраняются.
- **Глобальное заполнение лавой ниже Y=-54 остаётся ванильным.** Поэтому
  не обещается отсутствие лавы вдали от плит на самом дне мира. Это вариант 4
  из §10.1 плана: без перехвата GlobalFluidPicker.

Дискретность аквифера 40 блоков по Y не позволяет провести идеально точную
границу на каждом отдельном блоке Y=-40. Тесты проверяют выбор ветви по ячейкам.
В игре ещё нужно проверить корреляцию числа лавовых аквиферов с близостью плит.

## Проверки перед публикацией артефакта

CI запускает тесты ядра и мостов, полные эталоны на Linux/Windows, бенч;
собирает настоящий `.hnmod`; тестирует сгенерированный установщик паков;
планирует и применяет миксины точными закреплёнными версиями Horizon/Mixins,
затем выполняет `cargo check --locked --lib` для `horizon-core`,
`horizon-world`, `horizon-client-render` и `horizon-client`.

**Автоматические проверки пройдены** для кода `6415f36`:
[CI run 42383933103](https://github.com/Eblanitus/LithoMuchi/actions/runs/42383933103) —
все пять заданий зелёные: Linux fmt/clippy/tests, MSRV 1.85, Windows MSVC,
Windows GNU, упаковка с реальным plan/apply/компиляцией нативной интеграции.
Коллизионный тест явно чередует координаты (0,0)/(17,0), попадающие в один
слот: ложных попаданий нет. Проверки выбора/изоляции лавовых настроек тоже
выполнены в CI, а не только с помощью локального стенда.

Первоначальная вставка в STORE `settings_json` была отвергнута планировщиком
из-за `?` в инициализаторе. Рабочая вставка — первая запись `noise_clamped`
(два STORE в оригинале, выбирается ordinal 0): значение не меняется,
`settings_json` доступен через проверенный `$local_mut` capture. После применения
новые локальные крейты добавляются в lock командой `cargo update --workspace`,
без массового обновления внешних зависимостей. Это проверка исходников библиотек
на Linux, не доказательство запуска Windows-клиента или результата генерации в игре.

Ручные проверки ещё обязательны:

- [ ] Чистая установка: ровно два наших набора с иконками, исходно выключены.
- [ ] Отказ при выборе обоих режимов; создание с каждым по отдельности.
- [ ] Мир без наших паков, Nether и End не изменены.
- [ ] Scientific: загрузка и полёт при тех же настройках, что у контроля.
- [ ] LOD/обычные чанки согласованы; замеры относительно обычного Horizon.
- [ ] Стена и мезо-ледяной участок на исходном сиде, после перезахода.
- [ ] Выборка лавы около/вдали от границ плит (с учётом ванильного дна).
