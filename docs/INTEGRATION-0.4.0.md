# 0.4.0: лавовые аквиферы и собственная форма научного рельефа

## Граница разрешения автора

**Высота мира не увеличивается.** Build range остаётся -64…319 (384 блока),
море Y=63. Нет файлов dimension_type, dimension или noise_settings в наших
паках. T81 не выполнялась. Меняется форма рельефа, а не размер мира.
Для проверки — новый Normal-мир, один встроенный набор, один `.hnmod`.

Игровой режим сохраняет принятую геометрию 0.3.0. Научный намеренно меняется.
Все 6336 эталонов геологии/климата 0.3.0 продолжают совпадать побитово:
меняется перевод научной модельной высоты в игровую плотность и лавовый путь,
а не само тектоническое поле или климат.

## T80: научный рельеф определяется нашей высотой

У научного пака добавлены offset, постоянный factor=8 и jaggedness=0.
Пять C/E/W/T/H по-прежнему задают климат/биомы, но ванильные сплайны больше
не определяют основную научную высоту и не добавляют вторую независимую гору.

Вертикальный перевод (не масштаб мира по горизонтали):

- `surface_y = 63 + 28*e_km` для суши;
- `surface_y = 63 + 10*e_km` для океанических понижений;
- ограничение целевой поверхности: **-48…288**, с запасом до существующего дна/верха.

Примеры: e=-8 км → Y=-17 (жёлоб), -4.5 → 18 (абиссаль), 0 → 63 (берег),
+2 → 119 (плато), +7 → 259 (высокие горы). Это сжатие километров внутри
существующих 384 блоков, а не вертикальный масштаб 1:1.

В 26.3 глубина задана `depth = 1 - y/128 + offset`, поэтому наш адаптер
возвращает `offset = surface_y/128 - 1`. Число проверяется компиляцией реального
пакового графа в Horizon. У offset свой честный диапазон [-2,2], xz_scale=1,
y_scale=0; bulk считает колонку один раз, не пересчитывает её для каждого Y.
Для высоты используется только кора, **без повторного расчёта климата и лучей
переноса влаги**. Внутреннее Field::Offset сохраняет старую высоту в км;
преобразование выполняется на границе с Horizon.

**Сохранена исходная final_density с её пещерами**, материалами и аквиферами.
Старые внутренние terrain slides могли срезать собственные горы у Y=256 и
заполнять жёлоба у Y=-40. Только для нового научного маркера и Overworld
инлайн-копия final_density переносит верхнее затухание 240…256 → 288…312,
нижнее -64…-40 → -64…-56. Настройки noise.min_y/height, sea_level, dimension type
не меняются. Пещерные ветви графа не удаляются/не заменяются плоской функцией.
У старых научных паков без height_active эти изменения не включаются.

Это собственная **основа** высоты, не обещание, что верхний блок всегда стоит
ровно в surface_y: ванильный 3D-шум, пещеры, интерполяция, береговые/биомные
материалы продолжают влиять на конечные блоки. Стандартный Normal-пайплайн —
поддержанный сценарий; чужие переработанные графы и другие пресеты не заявлены.
Речное W и биомы сохраняются; отдельная собственная гидрологическая высотная
эрозия/вырезание русел в этой версии не добавлялись.

## T77: почему прежняя лава могла почти не встречаться

Horizon переводит fluid status в лаву при уровне жидкости <=-10 и
`abs(lava)>0.3`. Прежнее `lambda*random_factor` почти не пересекало этот порог
при малой lambda. Дополнительно мы разрешали только клетки Y<=-2:
это почти всё ниже глобальной ванильной лавы Y=-54, а важная клетка -1,
покрывающая -40…-1, вообще оставалась на старом шуме.

Теперь собственный выбор применяется к **отрицательным Y-клеткам**, включая -1.
Нативный порог уровня жидкости <=-10 сохранён; поверхностных излияний нет.
Lambda переводится в вероятность:

`p = 0.01 + 0.49*clamp((lambda-background)/(1-background),0,1)`

`value = 0.3 + 0.5*(p-cell_random)`

Выбор через нативный abs()>0.3 срабатывает с вероятностью p. У неактивных
отрицательных значений модуль строго меньше 0.3: зеркального ложного выбора нет.
Те же крупные детерминированные клетки 64×40×64. Вдали фон около 1%, у горячих
границ вероятность выше; это вероятность переключения **подходящего аквифера**,
не доля всех блоков мира и не автоматическое выкапывание полости.

GlobalFluidPicker не перехвачен: сплошная ванильная лава ниже -54 остаётся.
Без нашего пака, в Nether/End и при неоднозначных маркерах настройки не патчатся.
Никакие прежние чанки не переписываются.

## Автоматические проверки

- 64 unit-теста ядра, включая физическую высоту, границы и вероятностный порог;
- полный эталон 0.3.0 без пересъёмки, кэш/порядок/потоки, 3D-лава и 2D-offset;
- настройки проверяют сохранение min_y/height/sea_level, игровых графов и пещерных ссылок;
- упаковка декодирует байтовые массивы и сравнивает исходные паки побайтово,
  проверяет отсутствие размерностей/настроек высоты мира и offset в gameplay;
- CI применяет настоящий архив, проверяет загрузчик Horizon и компиляцию библиотек;
- **новые нативные тесты** компилируют паковые плотности в преобразованном Horizon,
  проверяют depth около целевой поверхности и точное масштабирование лавы;
- тест штатного `NoiseBasedAquifer` сравнивает одинаковые подземные аквиферы
  с включённым/выключенным лавовым сигналом выше Y=-54: проверяются реальные
  возвращаемые ID воды/лавы, а не только числа нашего поля.

Нативный тест с управляемыми floodedness/поверхностью проверяет сам путь выбора,
а не репрезентативное распределение всех настоящих пещер мира. Финальная
частота в игре и визуальный вид нового научного рельефа ещё не подтверждены.

## Воспроизводимая выборка поля

```sh
cargo run -p litho-core --release --example probe_lava -- -7249957072115989875 gameplay
cargo run -p litho-core --release --example probe_lava -- -7249957072115989875 scientific
```

8192 клетки на сиде автора, Y-клетка -1:

| Режим | Фон: активные/всего | Тёплые | Горячие (lambda>=0.4) |
|---|---:|---:|---:|
| gameplay | 59/6899 | 46/585 | 201/708 |
| scientific | 70/7123 | 57/632 | 138/437 |

Программа выводит активные наземные FIELD-клетки и команды TP для исследования
подземелья. Наличие пещеры/жидкости в конкретном блоке не гарантируется.
