Продолжение идеи закрытого PR #8 (`claude/column-cache`); план T160 целиком не завершён. `Generator::field` вычисляет семь текущих двумерных полей за один `sample` и хранит результат в ограниченном прямом кэше на 4096 слотов **для каждого потока**. Ключ — идентификатор экземпляра генератора и точные биты X/Z; клон генератора делит идентификатор. Разные миры и режимы не смешиваются, коллизия вытесняет слот. Кэш не удерживает генератор в памяти; память порядка сотен КБ на поток, выделяется при первом запросе. При добавлении зависимых от Y полей ключ и логика потребуют пересмотра.

Тесты сравнивают все семь полей побитово с прямым `sample` для двух режимов, разных сидов, координат и Y; проверяют попадание, вытеснение при коллизии, идентичность клона и отдельный поток. Хеши параметров v0 не изменились. Существующий `bench` теперь измеряет `sample`, а не прогретый кэш, чтобы не замаскировать регрессию скорости одного расчёта.

## Замер

Linux, Rust 1.99.0, release, один поток, сид `-7249957072115989875`, пять последовательных проходов по 16×16 колонкам; сначала пять расчётов `sample`, затем пять вызовов `field_column` с кэшем. Один прогон на общем раннере, суммы полей совпали побитово:

| Режим | Без кэша | С кэшем | Отношение |
|---|---:|---:|---:|
| gameplay | 0,244 с | 0,055 с | 4,43× |
| scientific | 0,246 с | 0,056 с | 4,36× |

Воспроизведение: `cargo run -p litho-sandbox --release -- bench-columns --seed -7249957072115989875 --mode gameplay` (заменить режим на `scientific`). Это микробенчмарк ядра, не тест Horizon: порядок запросов и объём рабочего набора в игре могут отличаться, а кэш и его коллизии влияют на выигрыш. Длительность полного создания чанков, LOD, загрузка CPU после генерации и работа нового бандла в игре **не проверены**. Реки, рельеф и визуальный результат здесь не менялись. Для завершения T160 нужны замеры в игре и проверка остальных бюджетов из плана.

Ближайшая задача критического пути пересмотренного плана — T100, предпросмотр высоты по локальным данным игры; эту задачу и запланированные после неё исправления рельефа данная оптимизация не заменяет.
