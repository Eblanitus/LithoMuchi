# Litospherity: переход на Fabric (черновик)

**Статус: принят автором 2026-11-15 (Д-105). 2026-11-17 автор сказал начинать сейчас, не дожидаясь v1 (Д-120).**
Horizon остаётся (пин 66f3981), его поддержка не ломается. Пока v1 не заморожен, эталон паритета — текущий `v1-dev` из `litho-core`.
Возможности Ф6 и выпуск Java-версии (Ф7) — отдельные решения автора.

## Зачем

- Horizon остаётся платформой релиза: молодая аудитория, встроенный дальний LOD.
- Java + Fabric нужна для двух вещей:
  - как стенд разработки — моды и инструменты под Java зрелее, а сама игра обновляется раньше Horizon;
  - как вторая платформа, где штатно делается то, что в Horizon заблокировано:
    - новые биомы (полубиомы на границах);
    - вода выше уровня моря;
    - выбор режима кнопкой «Тип мира».

Главный принцип: **ядро общее**.
- `litho-core` (около 19 тыс. строк) не меняется и не копируется.
- Под Horizon написано около 600 строк связки (`mod/glue`, `mod/packs`). Для Fabric пишется своя тонкая обёртка.
- Один сид и режим должны давать одинаковый мир на обеих платформах.

## Что переносится, а что пишется заново

| Часть | Horizon сейчас | Fabric |
|---|---|---|
| Наука: плиты, климат, реки, высота, биомы | `litho-core` | тот же `litho-core`, без правок |
| Вызов ядра | Rust внутри игры (миксины) | нативная библиотека `litho-ffi` (`.dll` / `.so` / `.dylib`), вызов из Java через Panama FFM (Java 25) |
| Наши поля C/E/W/T/H, offset/factor | подмена шумов `litospherity:*` хуком на `SeededContext::noise` | свой тип функции плотности, регистрируется в коде (`Registries.DENSITY_FUNCTION_TYPE`) |
| Датапак: `overworld/*`, `noise_settings` | паки `v1-dev` | те же JSON, встроены в jar мода |
| Выбор режима | пак в списке Data Packs (Д-100) | `world_preset` («Тип мира»: Litospherity геймплейный / научный); Horizon его не читает, Java читает |
| Лава у стыков (Д-097, Д-098) | хуки на аквифер Horizon | миксин на `NoiseBasedChunkGenerator.createFluidPicker` и аквифер |
| Дальний вид | встроенный LOD Horizon | Distant Horizons (строит даль из генератора) или Voxy + Chunksmith |
| Вода выше моря (R2) | ждёт `horizon-rust/horizon#16422` | тот же `FluidPicker` по колонке, штатно |
| Новые биомы | Horizon выкидывает | JSON-биомы внутри мода, штатно |

## Шаги кодера

**Ф0. Условие старта.** ~~v1 на Horizon выпущен (К10)~~ — снято автором 2026-11-17 (Д-120).
- Версия генератора `v1` заморожена с хешами (spec 6.8).
- Fabric-версия обязана давать тот же мир, что и `v1` на Horizon.

**Ф1. Крейт `litho-ffi` (Rust, `cdylib`).** Сделано 2026-11-17: `crates/litho-ffi`, CI `.github/workflows/ffi.yml`. Пакет отдаёт 10 полей `Field::ALL` в f32 (как Horizon); ячейка биома и уровень воды — добавить в Ф3, когда понадобятся Java.
- C-интерфейс к `Generator`:
  - создать и удалить генератор (сид, режим, версия);
  - пакетный запрос по колонкам: массив `(x, z)` на входе; C, E, W, T, H, PV, offset, factor, jaggedness, ячейка биома и уровень воды на выходе;
  - лава по ячейке аквифера.
- Звать по блоку нельзя: только пакетами по колонкам, с кэшем на чанк.
- Генератор потокобезопасный: Distant Horizons и C2ME зовут его из многих потоков.
- Готово, если:
  - тесты Rust сравнивают ответы `litho-ffi` с `litho-core` побитно;
  - CI собирает библиотеку под Windows x86_64, Linux x86_64, macOS (arm64 + x86_64).

**Ф2. Каркас мода Fabric.**
- Каталог `fabric/`: Gradle + Fabric Loom, Java 25, Minecraft 26.3, Fabric API.
- Нативные библиотеки лежат внутри jar; при запуске распаковываются и загружаются через FFM.
- Готово, если мод грузится в клиенте и на сервере всех трёх ОС и пишет в лог версию ядра и хеши параметров.

**Ф3. Генерация мира.**
- Тип функции плотности `litospherity:field` (поле, режим, версия). Кэш на колонку, пакетные вызовы из Ф1.
- Датапак Horizon `v1` переносится в ресурсы мода: те же `overworld/*`, та же ванильная таблица биомов по нашим T/H/C/E/W.
- `world_preset`: два типа мира, геймплейный и научный.
- Готово, если:
  - в одиночной игре создаётся мир каждого режима;
  - высота и биомы в 1000 контрольных точках совпадают с эталоном из `litho-core` (новый тест; `litho-sandbox checkpoints` даёт только 10 точек);
  - лава у стыков как в Horizon.

**Ф4. Паритет с Horizon.**
- Тест в CI: headless-сервер Fabric (gametest) генерирует область, и высоты/биомы сверяются с эталоном из `litho-core`.
- Расхождения с Horizon либо исправлены, либо описаны (например, порядок ванильных фич).
- Готово, если тест паритета зелёный в CI.

**Ф5. Скорость.**
- Замеры:
  - Chunky или Chunksmith: время прогенерации области;
  - spark: где тратится время;
  - Worldgen Devtools `/chunkprofiling`: время по шагам;
  - Distant Horizons: скорость построения дали.
- Совместимость с C2ME (многопоточная генерация).
- Готово, если генерация чанка не дороже, чем в Horizon, более чем на 30 % и в обоих режимах нет утечек памяти за час полёта.

**Ф6. Возможности только для Fabric** (после паритета, каждое — отдельное решение автора).
- Вода выше уровня моря (R2) и холодные пруды: `FluidPicker` по колонке (раздел 6 PLAN.md).
- Полубиомы на границах похожих биомов: скрипт генерирует JSON-биомы (средние цвета, деревья обоих биомов с половинной плотностью).
- Высота мира в научном режиме через `dimension_type`, если в Horizon её поднять не получится.
- Каждая возможность — новая версия генератора: миры `v1` не меняются (spec 6.8).

**Ф7. Выпуск Java-версии** (если автор решит выпускать).
- GitHub Releases.
- Modrinth: правила от 13.08.2026 запрещают проекты «в основном из ИИ-вывода» и требуют отметку «Contains AI-generated content». Решение и описание вклада автора — до заявки.
- CurseForge — сверить правила отдельно.

## Риски

- **Цена вызова Java → Rust.** Если FFM окажется дорогим даже пакетами, придётся считать в Rust целые чанки за один вызов.
- **Многопоточность Distant Horizons / C2ME.** Кэши ядра должны выдерживать параллельные запросы (`litho-core` уже параллелит климатическую решётку, Д-089).
- **Обновления Minecraft.** Fabric обновляется быстро, но API регистров и миксины на аквифер придётся сверять на каждой версии.
- **Переход Java на Vulkan.** Генерацию не затрагивает. Моды дальнего вида будут какое-то время нестабильны.
- **Оценка (грубая, без проверки):** Ф1–Ф5 — 2–4 недели работы кодера.
