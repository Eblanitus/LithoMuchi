Единицы T111 — `мм·L²/год`, не м³/с. Кольцо чужой плиты передаёт воду, но не добавляет локальный сток. На зеркале впадины приход считается как дождь `P·h²`, потеря — `PET·h²`; сухой сток `P-k_et·PET` там повторно не вычитается. Стартовые `climate_step_l=1.0`, `et_factor=1.0` записаны только в ключи `v1-dev`. Порядок накопления топологический; среди готовых узлов — по убыванию заполнения f, ничьи по номеру.

T112 переводит блочные стартовые ширины в L через масштаб режима: gameplay 4–28 блоков, scientific 6–60; `Q_min=25 мм·L²/год`, глубина 1.5/2.0 блока, долина ×5 на равнине и ×2 в горах. Меандры: `λ≈11·2w`, амплитуда `1.5·2w` на равнине и `0.3·2w` в горах; концы цепочки закреплены, чтобы слияния не разъезжались. Корзины 0.5 L — инфраструктура запроса, не параметр мира. T113 ищет уже не только ближайшую плиту: радиус по параметрам gameplay 1.250 L включает долину, меандр и переход к кольцевому узлу; T114 добавляет запас длины дельты, в замере gameplay 2.050 L. Выходы рифт/трансформ/море на кольце классифицируются по типу, поэтому в замере ниже незакрытых концов 0. Это не связывание Q соседних плит: ширина межплитовой реки постоянна (§5.5), а конец `Boundary` на других плитах остаётся честной диагностикой, а не фиктивным устьем.

Сеть пока использует `e_route = e_km`: потенциал рельефа A появится в T120. Замкнутая область с избытком воды получает статус `ClosedSurplus`, а не фиктивный выход; T114 строит контур влияния, но не выдаёт годовой избыток за уровень воды. `DepressionKind::Filled.spill_km` остаётся диагностикой priority-flood с ε-наклона, а поверхность озера берёт минимальную седловину выхода из рельефа; точное зеркало и уровни замкнутых/высоких озёр — T145. Кэш инфраструктурный (64 плиты), вытеснение не меняет ответ. Новые ключи `drainage.*`, `channels.*`, `lakes.*` входят только в canonical_text `v1-dev`; замок v0 не тронут.

T114 классифицирует поверхности по площади и климату: внутреннее море больше 1 L², болото не глубже 0.01 км при P/PET не ниже 1.2, замёрзшее озеро по самому холодному месяцу не выше 0 °C, берег сглаживается в пределах 0.5 шага решётки. Порог моря не отсекает высокие озёра: флаг `high` помечает необходимость R2, а не запрет v1. Дельты строятся при Q не ниже 500 мм·L²/год и уклоне не выше 0.005, главная полилиния укорачивается на длину веера, рукава расходятся от одной точки и делят расход. Соль `channels.delta` не меняет меандр T112. Это геометрия/диагностика, не игровое поле W и не перенос Q между плитами.

## Предпросмотр высоты

```bash
# Настоящие данные: путь к распакованной копии игры, где есть
# data/minecraft/worldgen/density_function/overworld/{offset,factor,jaggedness}.json
cargo run -p litho-sandbox --release -- render \
  --seed 42 --mode gameplay --version v1-dev --layers vanilla-height \
  --size 256 --bpp 32 --path fast --game-data /path/to/game --out out/height

# Метрики на тех же данных
cargo run -p litho-sandbox --release -- stats \
  --seed 42 --mode gameplay --version v1-dev --game-data /path/to/game \
  --span-l 200 --size 256 --relief-size 64 --relief-step 32 --json

# Без игры: только демонстрация CLI и тестов, НЕ приёмка и НЕ ваниль
cargo run -p litho-sandbox --release -- stats \
  --seed 42 --mode gameplay --version v1-dev --synthetic-height --size 64
```

Формула предпросмотра: `y ≈ 63.52 + 128·offset(C,E,PV)`, `PV = 1 − |3·|W| − 2|`. `factor`, `jaggedness` и трёхмерный шум читаются/разбираются, но в эту приближённую формулу не входят. Погрешность — несколько блоков. `blend_alpha` считается как новый мир (1), старая ветвь `blend_offset` не вычисляется. Неизвестные узлы и ссылки дают ошибку, а не молчаливую подмену.

Суша в новых метриках: `C ≥ ocean_c_threshold` и `river < 0.5`. Озёра T114 не подключены к высоте/`field()` до T115 и в этом предпросмотре не учитываются. Окна рельефа — отдельные 4×4 точки с шагом `--relief-step`, только целиком сухопутные. Основная сетка и сетка окон имеют разные шаги, это явно подписано в выводе. Синтетический сплайн помечен в тексте, JSON и подписи PNG; по нему нельзя объявлять достижение целей v1.

## Известные ограничения

- `--pv` пока возвращает понятную ошибку: собственного `Field::Pv` нет до T141. Сейчас PV всегда производная от W.
- Узкий знак W и старый инвариант `seams` конфликтуют на стартовых числах плана: при w_s=12 замер CI дал max \|ΔW\|=0.03478 при пороге 0.02. Порог не ослаблен; w_s расширен до 48/96. Это сглаживание знака, а не ширина русла: полоса \|W\|<0.05 остаётся порядка десятков блоков. Повторный замер прошёл; оценка вида на настоящих сплайнах — следующий шаг.
- В полях v1-dev до T115 остаются только локальные рифтовые/предгорные реки и шумовые ручьи. Трассы от истоков временно отключены в обоих путях, чтобы эталон и игра не расходились. Локальная река границы T113 — рифт/трансформ без предгорного «карандаша». Отдельные топография T110, расход T111, геометрия T112, общий запрос T113 и поверхности/дельты T114 уже считаются, но сеть в `field()` не подключена.
- Озёра T114 — диагностика: точные зеркала и уровни замкнутых/высоких озёр оставлены T145, холодные пруды по шуму плотности не реализованы, крупные межплитовые зеркала требуют индекса/бюджета T160. Высокие озёра помечены R2, но не отсекаются потолком высоты.
- Horizon/игра 26.3 в среде не запускались. T140/T142 и тест №2 автора остаются открытыми.
