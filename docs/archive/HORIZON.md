## 2. Что подготовлено в репозитории

- `mod/horizon-mixin.toml.in` — точка №1: cancellable HEAD, `[[module]]`, `[[crate]] dependent = "horizon-core"`, закрепление на `f319701e8c9ab657ff562250b3ba07b2d654e3bc`.
- `mod/glue/noise_hook.rs.in` — помощник, ровно одна приватная функция без атрибутов (иначе 5.4/5.5 отвергнут).
- `mod/glue/litospherity_glue.rs.in` — строгий разбор имени `litospherity:v0/<режим>/<поле>`, реестр `Generator` на `(seed, mode, version)`, `LithoNoise` с `field_column`, `ConstNoise` для smoke-пака. `add_to_volume` **намеренно оставлен комментарием**: заглушка по умолчанию зовёт `get3` для каждой точки объёма и молча даст неверную производительность, а точные типы `DensityVolume`/`DensityError` ещё не сверены.
- `mod/packs/*.in` — шаблоны `pack.mcmeta`, переопределения пяти `overworld/*` и фиктивные определения шумов. `base_amplitude = 4` с запасом накрывает [−1, 1]: граф берёт диапазон из JSON, а не из `range()` экземпляра (5.3).
- `tools/xtask` — `pack`, `bundle`, `bundle-check`: генерирует **пять** паков (`v0/scientific`, `v0/gameplay`, `v1-dev/scientific`, `v1-dev/gameplay`, `smoke`), собирает папку бандла с копией `crates/litho-core` и проверяет, что все файлы на месте и ни одного `@ПЛЕЙСХОЛДЕРА@` не осталось.
- `.github/workflows/ci.yml` — шаг «Э2 — шаблоны паков и бандла» без `|| true`. Он проверяет **целостность шаблонов**, а не совместимость с Horizon.

**Smoke-пак** (`litospherity_smoke`) — это ровно то, чего требует DoD: все пять
полей ссылаются на `litospherity:smoke/<поле>`, клей возвращает константу,
`continents = 0.8`. Если мир создаётся всюду сушей, точка №1 работает; если
рельеф ванильный — значит помощник не применился или имена шумов не дошли.

## 3. Чек-лист первой сборки на Windows (T70 → T72)

```text
horizon-launcher settings native-profile dev      # пересборка мода ~в 6 раз быстрее
cargo run -q -p xtask -- bundle --out out/bundle  # в репозитории, можно и на Linux
horizon-launcher native-build <папка out/bundle> --instance <имя> --trust-native-code
```

1. Выключить Smart App Control (иначе `os error 4551`, 5.6). Первая сборка 20–30 минут.
2. Записать сюда путь к `horizon-launcher` и дерево папки экземпляра (пункт 6).
3. Открыть `native/build.log`: мод должен примениться, а не исчезнуть с `E_TARGET_NOT_FOUND`.
4. Создать мир с типом **Normal** и только паком `litospherity_smoke`. Ожидание: всюду суша, в логе — наш генератор.
5. Затем мир с `litospherity_v0_scientific`, отдельно с `litospherity_v0_gameplay`. Включить ровно один пак (8.4).
6. Сверить пять ванильных файлов 26.3 и `aquifers.lava` (пункт 2); при расхождении обёртки поправить `mod/packs/density_function.json.in`.
7. Сверить точные пути типов в `litospherity_glue.rs`, реализовать `add_to_volume` по колонкам, проверить `range()` фиктивного определения.
8. Только после 1–7 записать в таблицу выше «ПРОВЕРЕНО» с датой, коммитом Horizon и логом.

**Ловушка среды.** `gh workflow run ci.yml --ref <ветка>` здесь возвращает
HTTP 403 `Resource not accessible by integration` (как и отмена run через API),
поэтому проверить конкретный HEAD можно только обычным push-коммитом. Коммиты с
`[skip ci]` полного прогона не имеют: всегда сверять `headSha` зелёного CI, а не
считать его автоматически относящимся к последнему коммиту.

## 5. I2-lite / T140–T141: подготовлено, НЕ ПРОВЕРЕНО в игре

T141 добавил в ядро `Field::Pv` и собственное значение PV в `WorldSample`.
Русла и низкие озёра режут PV к −1, поэтому долины I2-lite идут по воде, а не
по каждой смене знака W. Песочница `stats`/`render --layers vanilla-height`
принимает `--pv` и считает высоту/срез долины по этому полю.

`xtask pack` для `v1-dev` теперь пишет дополнительное переопределение
`data/minecraft/worldgen/density_function/overworld/ridges_folded.json`,
ссылающееся на шум `litospherity:<version>/<mode>/pv`. Паки `v0` остаются ровно
с пятью полями; `bundle-check` проверяет и наличие PV в v1-dev, и отсутствие
`ridges_folded` в v0. Это проверка целостности бандла, не совместимости с 26.3.

**T140 спайк заблокирован средой.** Нужно на Windows/ Horizon 26.3:
1. Сверить, что `minecraft:overworld/ridges_folded` существует и сплайны
   `offset/factor/jaggedness` ссылаются на него по имени.
2. Тестовый мир с PV=−1 на всей суше (сплошные долины) и PV=+1 (пики) при
   одинаковых C/E/W; проверить дальний рельеф.
3. Замерить скорость против ванили и записать артефакты сюда.
4. Если переопределение не работает, оставить путь через W с узким знаком и
   сообщить автору: без своей высоты T144/R2 невозможен.

Полная I2 T144 добавлена: `v1-dev` переопределяет также `offset/factor/jaggedness`
собственными полями ядра, всего восемь полей вместе с PV. `v0` остаётся с пятью
полями. Предпросмотр песочницы для `v1-dev` по умолчанию использует собственную
высоту без сплайнов Mojang; это **не** подтверждение работы пака в Horizon.

## 6. Полная I2 T144 и зеркала T145: НЕ ПРОВЕРЕНО в игре

В паке `v1-dev` проверить, что ванильные сплайны/граф 26.3 действительно берут
наши `offset/factor/jaggedness`, а не только что JSON-файлы существуют. Создать
отдельные миры gameplay/scientific, сравнить сушу/океан/горы с предпросмотром
песочницы и записать расхождения. Проверить, что `base_amplitude=4` для offset
накрывает рабочий диапазон, а factor/jaggedness остаются в допустимых пределах.

T145 считает зеркала рек/озёр и режет русла в собственной высоте ядра. Он **не
ставит блоки воды в игре**: постановка воды выше моря/R2 остаётся T143. В Horizon
проверить высокие озёра, монотонность рек вниз по течению, отсутствие воды выше
берега и производительность; до этого не объявлять R2 закрытым.

Данные Mojang в репозиторий не копируются.
