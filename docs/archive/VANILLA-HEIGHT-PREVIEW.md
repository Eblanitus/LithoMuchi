Инструмент предназначен для подбора будущих изменений рельефа; он не меняет генератор v0 и не подтверждает игровую высоту. Песочница читает три JSON-файла локально; игровые данные в репозиторий не включены. `serde_json` добавлен только в песочницу для безопасного разбора входного JSON; ядро остаётся без внешних зависимостей (Д-030).

## Использование

Подготовьте из своих локальных данных игры три файла: `offset.json`, `factor.json`, `jaggedness.json`. Параметр `--vanilla-data` принимает либо папку непосредственно с этими файлами, либо корень извлечённых данных, внутри которого они лежат в `data/minecraft/worldgen/density_function/overworld/`. Архив JAR автоматически не читается. Как получить эти JSON для конкретной версии, зависит от доступных игровых данных или генератора отчётов этой версии; файлы стороннего `misode/mcmeta` для 26.3 проверены этим предпросмотром, но не сверены с локальным JAR. Локальные файлы Mojang не коммитьте, например храните их вне репозитория или в игнорируемом `out/`.

```bash
cargo run -p litho-sandbox --release -- render --seed -7249957072115989875 --mode gameplay --path fast \
  --vanilla-data /путь/к/данным --layers vanilla-height --size 256 --bpp 32 --out out/height
cargo run -p litho-sandbox --release -- stats --seed -7249957072115989875 --mode gameplay --path fast \
  --vanilla-data /путь/к/данным --height-size 256 --height-bpp 32
cargo run -p litho-sandbox --release -- stats-all --path fast \
  --vanilla-data /путь/к/данным --height-size 64 --height-bpp 32
```

С `--layers all` слой высоты добавляется, только если задан `--vanilla-data`. `stats-all` выводит существующие метрики на области 200×200 L и затем локальные оценки высоты для 16 сидов и обоих режимов; локальная сетка по умолчанию имеет размер **2048×2048 блоков**, а не 200×200 L. `--height-size` — сторона квадратной сетки (не более 2048 точек); `--height-bpp` — шаг в блоках, делитель 128 не больше 64. Размер должен быть кратен числу точек в окне 128×128. Результаты перепада зависят от плотности сетки и учитывают лишь неперекрывающиеся окна, в которых все точки классифицированы как суша. Оценки на такой сетке не заменяют предусмотренного планом обследования 200×200 L на мелком масштабе.

Легенда карты: тёмно-синий — океан ниже 63, ярко-голубой — точки C ≥ −0,19, оценённые ниже 63 (возможное затопление), зелёные оттенки — 63–70 и 70–90, охра — 90–130, белый — 130 и выше. JSON рядом с PNG включает хеш параметров, путь расчёта и FNV-1a по содержимому трёх входных файлов для сравнения прогонов. Хеш не удостоверяет происхождение или версию игры.

Для саморазбора без игровых данных есть **искусственные**, не игровые примеры `crates/litho-sandbox/tests/synthetic-density/`; они проверяют код, но не годятся для оценки мира.

## Ограничения

- Вычисляется приблизительный ноль стандартного вертикального градиента `1 − y/128 + offset = 0`, т. е. `y ≈ 128·(1+offset)`, без трёхмерного шума, jagged noise, пещер, аквиферов, surface rules, blending старых чанков и особых настроек измерения. `factor` и `jaggedness` загружаются и вычисляются, но в эту оценку не входят. Даже при настоящих файлах это не точная поверхность или фактическое наличие воды.
- Поддерживается часть density functions, нужная для сплайнов и типичных обёрток (числа, C/E/W/PV, add, mul, abs, cache, spline и lerp с blend_alpha=1). Неизвестные выражения и неверные узлы дают ошибку, а не подставляются молча. Три файла `misode/mcmeta` с меткой 26.3 прочитаны и побайтно совпадают с прежней пробой snapshot; локальный JAR и фактическая поверхность в игре не проверены.
- В обычных `render`, `stats` и `stats-all` PV считается по W, `--pv` отклоняется. Для `render-hydro`, `stats-hydro` и `seams-hydro` с `--version v1-dev` можно явно передать `--pv`, чтобы оценить экспериментальное независимое поле I2-lite. Это не подтверждение его работы в игре: конечные выборки соседних блоков теперь проходят порог, но глобальная непрерывность не доказана. Нет настоящей метрики наличия воды: счётчик `r > 0,5` и высота ниже 63 — лишь косвенная диагностика.
- Нужны проверка на локальных игровых файлах и по контрольным точкам в Horizon, полные метрики на 16 сидах × 2 режима и калибровка экспериментального PV. Только после этого можно считать T100 завершённой и подбирать параметры T103.

Пример экспериментального сравнения (без `--pv` — старая свёртка W):

```bash
cargo run -p litho-sandbox --release -- stats-hydro --version v1-dev --mode gameplay --seed 42 --size 128 --bpp 32 --pv --vanilla-data /путь/к/данным
cargo run -p litho-sandbox --release -- seams-hydro --version v1-dev --mode gameplay --seed 42 --pv
```
Последняя команда проверяет конечную сетку: прохождение одного окна не гарантирует непрерывность повсюду.
