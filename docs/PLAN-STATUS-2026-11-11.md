## Что автору проверить в игре (тест №2, шаг 3)

1. Скачать `litospherity-hnmod` из артефактов CI и **ровно один** пак
   `litospherity_v1-dev_gameplay.zip`; положить `.hnmod` и включить пак при
   создании нового мира Minecraft Java 26.3 / Horizon `66f3981`.
2. Записать **сид** и **номер сборки/коммит** — без этого отчёт не приёмка.
3. Летать 15–20 минут в gameplay. Смотреть:
   - уровень моря и берега на месте (после К2 океаны не должны уйти на +64 блока);
   - равнины ровные, без «хаоса из парящих кусков» (factor/jaggedness пока ванильные);
   - горы есть и не превратились в стену;
   - реки похожи на реки и лежат в прорезанных долинах на уровне моря;
   - как быстро грузятся новые чанки и дальний рельеф, нет ли 99% CPU.
4. Отметить, воспроизводится ли плоская стена/меса рядом со льдом из отчёта
   2026-11-07, и приложить координаты/скриншоты.
5. Вернуть результат; только после этого открывать шаг 5.

## Правила процесса

- Невлитые ветки не удаляются; восстановленные `8beb6ac`, `arena/cc2bb388` и
  `arena/0192e968` остаются источниками, новая работа идёт одной линией.
- Каждый PR, трогающий то, что видно в игре, содержит строку «что автору
  проверить в игре».
- «Готово» у задач интеграции — только после игры. CI на настоящем Horizon
  проверяет контракт и граф, но не заменяет запуск мира.
- Экспериментальные паки `v1-dev-i2` из `arena/cc2bb388` в рабочий `.hnmod`
  **не входят**: их формулы и прототип описаны в исторических документах.

## Артефакты и команды

- `.hnmod` и все паки: `python3 tools/package_mod.py` после
  `cargo run -q -p xtask -- bundle --out out/bundle`.
- Проверка пинов: `python3 tools/check_horizon_pins.py`.
- Замер v1-dev: `cargo run -p litho-sandbox --release -- bench --seed 42 --mode gameplay --version v1-dev --chunk-target-ms 16`.
- Вердикт T151 (малый объём): `cargo run -q -p litho-sandbox --release -- acceptance --version v1-dev --seed 42 --mode gameplay --span-l 32 --size 32 --relief-size 8 --boundary-size 64 --boundary-step 32`.
