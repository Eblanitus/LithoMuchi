# T151: замер сидов на GitHub

Шаг 7 плана готовности: `stats --json` на 16 сидах × 2 режима против целей
`docs/PLAN-REVISION-2026-11-08.md`, 10.1.

## Как запустить

1. Изменить `tools/t151/request.json`: `name` (имя замера, каталог результата),
   `note`, при необходимости `seeds`, `modes`, `args`.
2. Отправить коммит в ветку. Workflow `.github/workflows/t151.yml` запускается
   на изменение этого файла; его также можно запустить вручную во вкладке
   Actions.

Замер идёт по коду того коммита, в котором изменён запрос. Поэтому правка
параметров генератора и новый `name` отправляются одним коммитом.

## Подбор: несколько вариантов за один замер

В запросе можно задать `variants`: у каждого своё имя, список режимов и строка
`set` для флага `stats --set ключ=значение,…` (список ключей — в
`crates/litho-sandbox/src/tune.rs`). Так несколько наборов параметров
сравниваются за один запуск без правки `Params::defaults`.

- `"results": "summary"` — в ветку пишется только `summary.md` (для кругов
  подбора); без него сохраняется и `results.json`.
- `"rows"` — какие метрики показывать, если объём замера урезан.

Замер с `--set` — подбор, не приёмка. Найденные значения переносятся в
`Params::defaults`, после чего идёт обычный замер без вариантов.

## Что получается

- Каждый прогон (режим × сид) идёт отдельным заданием на нативной сборке.
- Задание «Сводка» пишет `docs/t151/<name>/summary.md` и
  `docs/t151/<name>/results.json` отдельным коммитом в ту же ветку.
- **`name` — это адрес записи.** Папка перезаписывается целиком
  (`rm -rf docs/t151/$NAME`), поэтому при смене кода, параметров или флагов
  имя обязано меняться. Иначе новый прогон молча затрёт прошлый отчёт, и
  документы, ссылающиеся на эту папку, начнут описывать не то, что в ней
  лежит. Так уже случилось: `plan-metrics2` (прогон с правкой T123) был
  затёрт прогоном на откаченном коде, см. Д-071 и раздел «Судьба папки
  `plan-metrics2`» в `docs/STEP7-METRICS-2026-11-12.md`.
- Упавший прогон не прячет остальные: он попадает в раздел «Упавшие прогоны»
  сводки вместе с хвостом stderr, а сам замер становится красным.

## Локально

    python3 tools/t151/report.py <каталог с <режим>_<сид>.json> [--out <каталог>]

Скачок влажности в сводке считается тремя способами: по климатической суше,
по полю H на всей суше и по меткам биомов на всей суше. Последний почти целиком
состоит из кромок русел (у них служебный класс влажности), поэтому под него
параметры не подбираются; строка «Скачки по меткам биомов» показывает, из чего
он сложен.

Сводка только считает, сколько сидов попало в цель. Вердикт приёмки 10.1 по
границам требует полного объёма (сетка границ на ≥ 200 L с шагом ≤ 32 блока);
строка «в приёмочном объёме» в сводке показывает, выполнено ли это.
